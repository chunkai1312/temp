# Query Normalization Rules v2（Phase 2 規格骨架）

此檔定義在拆解法律問題後，如何將口語問題正規化成較穩定的檢索表示。

---

## 一、正規化目標

1. 把口語、縮寫、俗稱轉成正式術語
2. 把模糊主體轉成可檢索的實體
3. 保留否定、例外、但書語氣
4. 避免只用原句字面搜尋造成漏檢

---

## 二、正規化輸出

內部應形成下列結構：

```json
{
  "raw_query": "",
  "normalized_query": "",
  "normalized_entities": [],
  "normalized_actions": [],
  "normalized_objects": [],
  "expanded_keywords": [],
  "negative_terms": [],
  "exception_terms": [],
  "law_refs_hint": []
}
```

---

## 三、常見正規化規則

### 1. 用語統一
- 利關人 → 利害關係人
- 董監事 → 董事、監察人
- 總座 → 總經理
- 概括授權 → 董事會概括授權 / 授權經理部門
- 建檔 → 建檔 / 維護 / 申報
- 解除 → 解除申報 / 刪除 / 終止維護（視上下文判斷）

### 2. 親屬稱謂統一
- 公婆 / 岳父母 → 一姻候選詞
- 配偶的兄弟姊妹 → 二姻候選詞
- 兄弟姊妹的配偶 → 二姻候選詞
- 前婚姻關係子女 → 需同時展開 1血/1姻 候選與正式法源確認需求

### 3. 公司名稱辨識
若使用者只說：
- 創投
- 證創投
- 租賃
- 銀行
- 證券

應先比對是否存在多個相似主體，必要時加上：
- 集團架構檢查
- 直接/間接持股判斷
- 是否同屬 100% 持股體系

### 4. 法條線索展開
- 金控法45 → 金融控股公司法第四十五條
- 銀行法33-1 → 銀行法第三十三條之一 / 第七十五條相關利害關係人定義（依資料實際記載）
- 概括授權 → 第四十五條 / 金管銀法字第11202738872號令 / 內規第三條（視命中資料）

---

## 四、否定與例外詞不可遺失

下列詞語一旦出現，不得在正規化時被刪除：
- 不得
- 不可以
- 不在此限
- 但
- 但書
- 除外
- 例外
- 不適用
- 免申報
- 無須

這些詞直接影響義務方向與例外判斷。

---

## 五、擴展關鍵詞策略

### A. 條號型
保留：
- 法規全名
- 條號
- 法規別名

### B. 爭點型
展開與爭點直接相關的法律術語。

### C. 主體型
展開公司別、業別、身分類型。

### D. 例外型
把但書、例外、排除條款常見詞一起加入。

---

## 六、不得做的事

1. 不得把使用者問題過度改寫到失去原意。
2. 不得把推測出的法條當成既定事實。
3. 不得刪除否定詞、例外詞、時間詞。
4. 不得因常識而補上資料中沒有的法規名稱。

---

## 七、給 SKILL 的執行摘要

1. 先保留原始問句
2. 再做正式術語轉換
3. 補足主體/行為/客體候選詞
4. 保留否定與例外詞
5. 再把結果交給法源過濾與檢索
