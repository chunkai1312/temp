# Source Validation Checklist v2（Phase 3 規格骨架）

此檔定義在完成檢索與重排後，如何做 **逐項法源驗證**。

> 目前狀態：**先建立驗證清單骨架，不要求現階段已有完整版本法規庫或 citation graph。**

---

## 一、驗證目的

檢索命中不代表就能回答。

逐項法源驗證的目的是確認：
- 打算說出的每一個重要結論
- 是否都能被具體法源支持
- 是否已處理例外、但書、特別規定、責任條文與版本問題

若做不到，應回答「目前無法確定」，而不是補完。

---

## 二、驗證單位

驗證以「準備輸出的每一項重要陳述」為單位，不是只看整段答案大致合理即可。

### 重要陳述例子
- 本案屬利害關係人交易
- 本案需提董事會核議
- 本案屬概括授權範圍
- 配偶的兄弟姊妹屬二姻
- 銀行子公司董事長需申報二親等內姻親
- 應於每月 8 日前完成申報

每一項都要能對應具體法源。

---

## 三、逐項驗證欄位

建議對每一項重要陳述至少產生：

```json
{
  "claim": "",
  "supporting_sources": [],
  "subject_supported": true,
  "counterparty_supported": true,
  "action_supported": true,
  "modality_supported": true,
  "conditions_supported": true,
  "exceptions_checked": true,
  "liability_checked": true,
  "version_status": "confirmed|partially_confirmed|unconfirmed",
  "support_level": "supported|partially_supported|unsupported|uncertain",
  "notes": ""
}
```

---

## 四、逐項檢查問題

### 1. 主體是否正確
- 條文規範的主體是否就是本案主體？
- 金控、銀行、證券、子公司、董事、經理人是否混用？

### 2. 相對人 / 客體是否正確
- 親屬範圍、交易對象、資料對象、申報對象是否一致？

### 3. 行為是否正確
- 問的是授信、投資、捐贈、建檔、申報、查詢、解除申報，候選條文是否真在規範同一行為？

### 4. 規範型態是否正確
- 條文是在說應為、不得為、得為、權利，還是只是背景說明？

### 5. 成立要件是否完整
- 金額、持股比例、親等、身分、時間點、程序條件是否完整查核？

### 6. 例外與但書是否查核
- 是否存在會反轉或限縮結論的但書 / 排除條款 / 例外？

### 7. 責任或法律效果是否真適用
- 若答案提到責任、罰則、董事會核決、申報期限，是否有對應條文支持？

### 8. 版本與效力是否可確認
- 若問題是現況題，能否確認引用的是有效版本？
- 若不能確認，是否已在答案中揭露？

---

## 五、支援程度分級

### `supported`
- 法源明確支持該陳述
- 主體、行為、條件、例外均無重大缺口

### `partially_supported`
- 法源只支持部分陳述
- 仍有條件、例外、責任或版本缺口

### `unsupported`
- 找不到法源支撐該陳述
- 或找到的法源其實不適用本案

### `uncertain`
- 版本、法域、事實或共同適用關係仍無法確認

---

## 六、重大警訊（Hard Fail）

以下任一出現，即使其他部分看似合理，也不得直接下定論：

1. 關鍵例外 / 但書未檢查
2. 義務主體不一致
3. 用 FAQ / 教育訓練支撐正式法規結論
4. 用版本不明或可能失效條文回答現況題
5. 引用的法源其實只談相似議題，不談本案要件

---

## 七、現階段 v1 資料下的保守做法

由於目前仍沿用 v1 RAG JSONL，逐項驗證時應特別注意：

### 可做的
- 檢查條文文字是否真有支持主體 / 行為 / 要件
- 檢查 FAQ 是否只屬相似案例而非直接同案
- 檢查教育訓練是否只是補充說明
- 檢查是否明確提到日期、期限、但書、責任

### 尚難完整做到的
- 版本效力完整確認
- 官方來源交叉驗證
- 上下位法 / 引用圖譜的完整閉環驗證

因此若版本欄位不足，應標：
- `version_status = unconfirmed`
- 或 `partially_confirmed`

---

## 八、驗證後如何決定回答策略

### 可正常回答
若主要陳述均為 `supported`，可依證據式模板回答。

### 應保守回答
若任一關鍵陳述為：
- `unsupported`
- `uncertain`
- `version_status = unconfirmed` 且本案為高風險現況題

則應回答：
- `目前無法確定。`
- 並明示缺口是：法域、版本、例外、主體、條件或正式法源不足。

---

## 九、給 SKILL 的執行摘要

1. 每項重要結論都要單獨驗證
2. 驗證主體、行為、條件、例外、責任、版本
3. 支持不足就降級為保守回答
4. 不可把檢索命中當成已驗證完成
