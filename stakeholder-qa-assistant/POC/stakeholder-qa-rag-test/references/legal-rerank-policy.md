# Legal Rerank Policy v2（Phase 3 規格骨架）

此檔定義 v2 檢索流程中的 **法律重排** 原則。

> 目前狀態：**先建立重排規格骨架，不要求現階段一定有法律專用 cross-encoder 或 reranker 服務。**

---

## 一、重排的任務

法律重排不是單純把「最像問題的文字」排前面，而是要把：
- 真正處理**同一法律爭點**
- 且對應**正確主體 / 客體 / 行為 / 法域 / 時間範圍**
- 並包含**成立要件、例外、但書、責任或法律效果**

的候選條文排到前面。

---

## 二、輸入與輸出

### 輸入
來自雙路召回 + RRF 後的候選法源，通常 50～100 筆。

### 輸出
縮至約 10～20 筆較可信的法源候選，供後續逐項驗證。

---

## 三、重排評分面向

每一候選至少從以下面向評估：

### 1. 爭點一致性
- 是否真在回答同一法律問題
- 是否只是表面字詞相似但實際爭點不同

### 2. 主體一致性
- 條文規範的主體是否與問題主體一致
- 例如金控、銀行子公司、董事、經理人不可混用

### 3. 客體 / 相對人一致性
- 交易對象、親屬對象、資料對象、申報對象是否一致

### 4. 行為一致性
- 授信、捐贈、投資、建檔、申報、查詢等行為類型是否一致

### 5. 規範型態一致性
- 問題是在問：
  - 應為
  - 不得為
  - 得為
  - 權利
- 候選條文是否真在回答該型態

### 6. 例外 / 但書完整性
- 候選條文是否包含或指向本案可能改變結論的但書、例外、排除條件

### 7. 責任 / 法律效果完整性
- 若問題涉及責任、罰則、核決流程、申報義務，候選是否真有對應內容

### 8. 法域與位階一致性
- 是否屬正確法域
- 是否應由外規優先，而不是內規或 FAQ 排前

### 9. 版本 / 效力可確認性
- 若候選的版本效力可疑，不應排在需要現況判斷的高優先位置

### 10. 共同適用需求
- 某條文是否需要與另一條文合併理解，不能單獨當答案來源

---

## 四、建議輸出欄位

重排後每筆候選至少應附帶以下內部欄位：

```json
{
  "record_id": "",
  "rerank_score": 0.0,
  "issue_match": "high|medium|low",
  "subject_match": "high|medium|low",
  "counterparty_match": "high|medium|low",
  "action_match": "high|medium|low",
  "modality_match": "high|medium|low",
  "exception_coverage": "high|medium|low|unknown",
  "liability_coverage": "high|medium|low|unknown",
  "authority_level": "external|internal|faq|training|reference",
  "version_confidence": "high|medium|low|unknown",
  "needs_joint_application": true,
  "notes": ""
}
```

## 五、重排後的保留原則

### 優先保留
- 外規或正式法源
- 問題主體 / 客體 / 行為高度一致的條文
- 包含例外 / 但書或責任條文的關鍵條文
- 與本案高度相關且可能共同適用的條文組合

### 可降權但不一定刪除
- FAQ 相似案例
- 教育訓練摘要
- 圖示或輔助整理

### 應大幅降權
- 法域明顯不符
- 主體或行為明顯不符
- 只含一般性敘述、不足以直接支持結論
- 版本效力明顯不明且本案又是現況題

---

## 六、Heuristic fallback（現階段可落地）

若現階段尚未接法律模型，可先用規則式加權，至少考慮：

1. 條號精準命中 +
2. 法規名稱精準命中 +
3. 主體一致 +
4. 客體一致 +
5. 行為類型一致 +
6. 規範型態一致 +
7. 例外 / 但書 / 責任條文存在 +
8. 外規位階高於內規、FAQ、教育訓練 +
9. 版本效力不明 -
10. 法域不明或不合 -

### 重要限制
這只能稱為：
- 規則式重排
- heuristic rerank

**不得對外宣稱已使用法律專用模型。**

---

## 七、共同適用（Joint Application）規則

有些問題不能只靠單一條文回答，重排時要特別標記需共同適用者。

### 常見情況
- 主文 + 但書
- 行為要件 + 例外條件
- 一般規定 + 特別規定
- 實體規範 + 程序規範
- 行為規範 + 責任條文

### 原則
若某候選條文本身不足以單獨支撐回答，但顯然是關鍵組件，應保留並標 `needs_joint_application=true`。

---

## 八、重排失敗的警訊

出現以下狀況時，應視為重排品質不足：

1. 前段候選多為 FAQ / 訓練資料，正式法源被壓後
2. 前段候選只字面相似，但主體 / 客體不同
3. 只排到一般規定，漏掉特別規定或但書
4. 責任問題卻沒排到責任條文
5. 現況題卻排到版本不明或歷史條文

若出現上述警訊，後續回答應更保守。

---

## 九、給 Source Validation 的交接要求

重排後交給驗證階段時，至少要能說明：
- 為何選這些候選
- 這些候選是否涵蓋主體、行為、例外、責任
- 哪些候選需共同適用
- 哪些地方版本效力仍不穩

---

## 十、給 SKILL 的執行摘要

1. 重排不是找最像的字串，而是找最適用的法源
2. 主體 / 客體 / 行為 / 規範型態 / 例外 / 責任都要看
3. 外規與正式法源優先
4. 需共同適用的條文不可過早刪掉
5. 重排不足時，回答要更保守
