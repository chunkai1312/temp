# Consistency Check Rules v2（Phase 4 規格骨架）

此檔定義在完成結構化抽取後，如何檢查抽取結果與回答草稿之間的一致性。

> 目前狀態：**先建立一致性檢查規格骨架，不要求現階段已具備完整自動檢查程式。**

---

## 一、檢查目的

結構化抽取的目的不是把條文切成欄位而已，而是要避免以下高風險錯誤：

1. 義務主體抓錯
2. 把定義條文當成義務條文
3. 漏掉關鍵但書或例外
4. 一般規定覆蓋特別規定
5. 將責任條文錯套到本案
6. 引用的法源其實只支持背景，不支持結論

---

## 二、檢查層次

至少分三層：

### 1. 單筆抽取內部一致性
檢查同一筆 `norm_extraction` 內部欄位是否互相矛盾。

### 2. 多筆抽取之間一致性
檢查不同法源抽取之間是否存在衝突、補充、特別法優先或共同適用關係。

### 3. 抽取與最終回答一致性
檢查回答中每一項重要結論，是否真的被抽取結果支持。

---

## 三、單筆抽取內部一致性

### 檢查 1：主體與規範型態是否對齊
- 若 `modality = must / must_not / may / right`，則 `subject` 不得為空。
- 若 `subject` 不明，但回答卻寫成明確義務主體，視為重大風險。

### 檢查 2：定義條款不得偽裝成義務條款
- 若 `modality = definition`，不得直接產出「應」「不得」「需提董事會」等結論。
- 定義條款只能支撐範圍、身分、概念判斷。

### 檢查 3：程序條款不得偽裝成實體禁止規範
- 若 `modality = procedure`，不得直接推導為「禁止」或「允許」，除非另有主文支撐。

### 檢查 4：例外 / 但書欄位是否遺漏
- 若條文文字含「但」「但書」「不在此限」「除外」「不適用」等，`exceptions` 不得空白。

### 檢查 5：期限與效果是否混淆
- `deadline` 應只放時間要求。
- `legal_effect` 應放核決、申報、准駁、程序效果。

### 檢查 6：責任不得憑空生成
- `liability` 只可在法源明示時填入。
- 若無責任條文，不得由違反程序自行推導罰則。

---

## 四、多筆抽取之間一致性

### 檢查 7：一般規定與特別規定
- 若同時有一般條與特別條，應優先適用特別條。
- 回答時不得只引一般規定而忽略更具體的特別規定。

### 檢查 8：外規與內規的位階
- 外規高於內規。
- 內規只能補充，不得推翻外規。

### 檢查 9：FAQ / 訓練資料的位階
- FAQ 可作相似案例參考。
- 教育訓練僅作輔助理解。
- 若 FAQ / 訓練資料與正式法源不同，應以正式法源為準。

### 檢查 10：共同適用需求
- 若一筆抽取標記 `claim_scope = joint_application`，回答不得只引用其中一條就下完整結論。

### 檢查 11：版本衝突
- 若兩筆抽取來自不同版本，且版本效力未能確認，不得合併成單一確定結論。

---

## 五、抽取與回答一致性

### 檢查 12：回答中的主體是否來自抽取
- 若回答中出現明確主體，但抽取欄位沒有相應 `subject` 支撐，視為不一致。

### 檢查 13：回答中的例外是否已查核
- 若回答給出肯定結論，但抽取中 `exceptions` 為空且原文疑似有但書，視為高風險。

### 檢查 14：回答中的責任 / 法律效果是否有支撐
- 若回答提到需提董事會、不得辦理、應申報、應上傳、應迴避等，必須在 `legal_effect` 或 `liability` 找到依據。

### 檢查 15：回答中的引用是否超出法源支持範圍
- 若 `citations.support_scope = partial` 或 `context_only`，不得把該引用當成完整結論依據。

---

## 六、重大錯誤（Hard Fail）

出現以下任一情況時，不應直接輸出確定答案：

1. 義務主體與抽取主體不一致
2. 有但書線索但 `exceptions` 空白
3. 把 FAQ / 教育訓練結論直接當正式法規結論
4. 共同適用條文只引用其中之一
5. 版本不明卻回答現況題
6. 責任條文未支撐卻宣稱有責任或法律效果

---

## 七、建議的一致性檢查輸出

內部可產生：

```json
{
  "consistency_status": "pass|warning|fail",
  "checks": [
    {
      "check_name": "subject_binding",
      "status": "pass|warning|fail",
      "evidence": ""
    }
  ],
  "major_risks": []
}
```

### 狀態意義
- `pass`：未發現重大矛盾
- `warning`：可回答，但需揭露限制
- `fail`：不得輸出確定結論

---

## 八、給 SKILL 的執行摘要

1. 先檢查單筆抽取是否自洽
2. 再檢查多筆抽取是否有位階或特別法衝突
3. 最後檢查回答是否真的被抽取欄位支撐
4. 只要出現主體錯綁、但書遺漏、責任誤套或版本不明等重大問題，就改採保守回答
