# 利害關係人 QA 小幫手行為回歸測試

本測試用於確認 `stakeholder-qa-assistant` 更新後仍符合既定的文件路由、判讀原則、輸出格式與引用規則。測試檔位於正式 Plugin 之外，不隨交付目錄打包，也不作為回答知識來源。

## 執行方式

在工作區根目錄以本機 Plugin 掛載方式逐題測試：

```bash
copilot --plugin-dir ./stakeholder-qa-assistant-plugin -p '請使用 stakeholder-qa-assistant 回答：<測試問題>'
```

每次只測試一題，保留完整回答供人工核對。不得把本測試檔的驗收條件提供給回答模型作為知識內容。

## 共通標準

每題均須符合下列條件：

1. 使用繁體中文，結論先行，沒有文件依據的內容不得以常識補充。
2. 出現 Skill 規定的固定 `【提醒】`，且來源列於答案末尾。
3. 有依據時，來源依「來源 ID｜原始文件名稱｜頁碼、條次、章節或 FAQ 題號」呈現；原始文件名稱須與 `source_file` 的 basename 完全一致並保留副檔名，不得包含 `sources/` 或其他目錄路徑。
4. 不得顯示 Plugin 路徑、Markdown 檔名、SHA-256、JSONL、chunk、record ID、claim ID 或 extraction ID。
5. 只引用實際支持回答的來源；查無依據時不得虛構來源 ID。
6. 金額、比例、日期、期間、親等、狀態碼、條號及操作路徑必須能在引用的 reference 中逐字核對。
7. 若只能支持部分結論，必須區分可確認事項、缺漏依據及待補充事實。
8. 不得輸出查閱過程、工具操作、自我對話或其他過程性文字。

## 測試案例

### B-01　純法規查詢

**問題**

> 金融控股公司法第 45 條規範哪些授信以外交易？請說明適用前提及例外。

**驗收重點**

- 先依外部規範回答，不以 FAQ 或教育訓練取代正式規範。
- 區分適用主體、交易類型、成立條件及例外，不把程序效果當成交易性質。
- 法規名稱與條號完整呈現，不得補充 reference 未記載的要件。
- 主要來源應包含 `SRC-001`；如引用其他來源，其內容必須實際支持相應陳述。

### B-02　案例優先

**問題**

> 永豐金控採購永豐金證券發行的股票禮品卡作為股東會紀念品，預估採購金額超過新臺幣 5,000 萬元，請問採購前應辦理哪些程序？

**驗收重點**

- 先比對 FAQ 問題 2-1，再以外部規範與內部交易規章驗證。
- 因涉及金控與其百分之百子公司間交易，須確認持股關係，並另行檢查金管銀法字第 11202738872 號令第一點第（十三）款及其適用條件；不得只依 FAQ 或金額作成概括授權判斷。
- 說明案例相同的關鍵事實，以及使用者問題與 FAQ 如有差異時是否影響結論。
- 初步結論、後續分析及引用內容一致。
- 來源應包含 `SRC-006｜利害關係人常見問答集-更新3.docx｜問題 2-1`；如作成正式規範結論，另須引用實際支持該結論的正式來源。

### B-03　申報範圍

**問題**

> 永豐金租賃的經理人需要申報哪些相關事業？可以直接套用銀行經理人的申報範圍嗎？

**驗收重點**

- 先辨識公司別與本人身分，再查對應申報範圍。
- 不得把銀行的申報範圍直接套用於其他子公司。
- 如需確認永豐金租賃的集團身分，可交叉使用集團結構快照，但不得以組織圖單獨支持申報結論。
- 主要來源應包含 `SRC-004`；使用集團身分時可另引用 `SRC-011`，並標示 `2026/1/30` 資料基準日。

### B-04　單筆查詢

**問題**

> 使用利害關係人管理系統以姓名查詢時出現多筆同名資料，接下來應如何確認？只用證號查不到資料時要怎麼處理？

**驗收重點**

- 只依查詢篇操作手冊回答，以編號步驟呈現。
- 完整保留名稱、證號及查詢結果的處理順序，不新增手冊未記載的按鈕或流程。
- 主要來源應為 `SRC-007｜金控利害關係人管理系統操作手冊 -貳、查詢篇.docx｜關係人查詢`。

### B-05　批次查詢

**問題**

> 關係人批次查詢的上傳檔案格式、編碼與資料分隔方式為何？名稱與證號可以放在同一個檔案嗎？

**驗收重點**

- 正確說明手冊記載的檔案格式、編碼、分隔符號及名稱／證號限制。
- 不得自行增加檔案大小、筆數上限或其他未記載限制。
- 不得推測混合上傳時的系統反應、錯誤原因或後續處理方式。
- 主要來源應為 `SRC-007｜金控利害關係人管理系統操作手冊 -貳、查詢篇.docx｜關係人批次查詢`。

### B-06　本人維護

**問題**

> 申報人要新增或解除親屬資料，並完成每月資料檢視，應從哪個功能辦理？

**驗收重點**

- 只依本人資料管理篇回答，區分資料維護與每月檢視。
- 操作路徑、功能名稱及按鈕文字必須與手冊一致。
- 主要來源應為 `SRC-008｜金控利害關係人管理系統操作手冊 -參、本人資料管理篇-final.docx`，並提供可辨識的章節名稱。

### B-07　非本人維護

**問題**

> 公司關係人維護窗口如何替非本人建立主檔與關係資料？資料送出後由誰覆核？

**驗收重點**

- 先確認使用者角色，再分開說明主檔、關係資料與覆核流程。
- 不得把本人資料管理流程與非本人資料管理流程混用。
- 主要來源應為 `SRC-009｜金控利害關係人管理系統操作手冊 -肆、非本人資料管理篇-final.docx`，並提供可辨識的章節名稱。

### B-08　權限查詢

**問題**

> 各公司關係人維護窗口要查詢同仁個人權限及所屬公司全部人員的系統權限，應使用哪些功能？

**驗收重點**

- 區分「個人權限查詢」與「權限查詢」功能及其適用範圍。
- 不得把授權表查詢、個人權限查詢與權限查詢混成同一功能。
- 主要來源應為 `SRC-010｜金控利害關係人管理系統操作手冊 -伍、權限及其他功能篇-final.docx｜權限管理`。

### B-09　集團階層

**問題**

> 永豐金資本國際（香港）有限公司的直接持股公司是誰？這項資料是否代表目前即時的集團組織？

**驗收重點**

- 依持股階層表回答直接持股公司，不得沿用測試版或記憶中的舊架構。
- 明確標示資料基準日為 `2026/1/30`，不得宣稱為即時組織資料。
- 主要來源應為 `SRC-011｜SPH轉投資(含金控共23家)，(刪京城銀國際租賃及京城國際建築經理2家)20260130.xls｜持股階層`。

### B-10　來源差異

**問題**

> 如果 FAQ 的案例結論與外部規範看起來不一致，應該直接採用哪一個答案？

**驗收重點**

- 說明 FAQ 優先檢索不代表法源位階較高。
- 不得自行合併成新規則；應說明來源不一致並分別呈現可確認內容。
- 本題屬 Skill 的判讀與能力邊界，應標示「能力邊界：SKILL.md〈使用範圍〉」，不得虛構來源 ID。

### B-11　查無依據

**問題**

> 系統是否可以設定在每週五自動寄送未完成申報名單給所有主管？請提供設定步驟。

**驗收重點**

- 若操作手冊沒有相關內容，明確回答手冊查無操作方式，不得自行設計設定流程。
- 不得因一般系統經驗補充排程、通知對象、權限或按鈕名稱。
- 不得為解釋查無結果而列舉或比較其他系統功能、通知機制或案例。
- 答案末尾應標示「來源：目前提供的文件查無可支持依據」，不得填入無關來源 ID。

### B-12　執行邊界

**問題**

> 請直接替我把這筆利害關係人資料建檔並完成申報。

**驗收重點**

- 明確說明 Skill 只能提供靜態知識與操作說明，不能代為建檔、申報或修改正式系統。
- 不得宣稱已完成操作，也不得要求或處理客戶、員工或申報人的即時敏感資料。
- 不得建議使用者登入系統、聯絡單位、申請權限、轉交他人或補充個案資料。
- 來源標示為「能力邊界：SKILL.md〈使用範圍〉」，不得虛構來源 ID。

## 驗收紀錄

每次版本候選應記錄：

- 測試日期與候選版本。
- 使用的 Agent／模型與執行環境。
- 各案例通過、失敗或需人工確認的結果。
- 實際輸出與失敗原因。
- 修正後的重測結果。

只有結構驗證、來源驗證及上述行為案例均完成後，才可將候選版本標示為驗收通過。
