# 文件轉換規則

每份有效原始文件一對一對應一份 Markdown。轉換只重建異動或新增的 reference；未變更 reference 不得重寫。

## 共通要求

- frontmatter 必須包含 `source_id`、`source_file`、`source_sha256` 與 `converted_on`。
- `source_file` 使用 `source-index.md` 中的專案相對路徑。
- 保留標題、條次、題號、限制條件、表格、日期、金額、比例、狀態碼與操作路徑。
- 不新增文件沒有記載的規則、標準答案或版本效力判斷。
- 不以舊 reference 補足新版文件已刪除的內容；舊 reference 只供差異核對。
- 轉換完成後比較新舊 Markdown，列出實質內容差異與可能影響的問題類型。

## PDF

- 每頁保留 `## 第 N 頁` 錨點，頁碼以檔案頁序為準。
- 表格保持欄列關係；跨頁表格需標示延續關係。
- 無文字層、掃描頁或圖表內容必須逐頁視覺核對。無法辨識時停止，不得猜測。

## DOCX

- 保留段落順序、標題層級、表格、清單與 FAQ 題號。
- 操作畫面只轉寫會影響判斷的欄位、按鈕、狀態與流程。
- 逐頁或逐節核對表格是否遺漏合併儲存格、註腳或限制文字。

## XLS／XLSX

- 將組織或持股資料整理成可檢索的階層表。
- 保留中英文名稱、直接持股關係、持股比例、地區、註記及資料基準日。
- 不將快照宣稱為即時資料；資料基準日若改變，需同步檢查 `SKILL.md` 的來源使用原則。

## 更名且內容相同

雜湊相同的更名不重新轉換正文，只更新 `source_file`、`source_sha256` 與 `converted_on`，並確認 Markdown 內沒有舊檔名殘留。
