# InfoGather 資訊收錄智能平台專案需求說明書

日期：2026-11-06　｜　文件屬性：機密文件

本專案擬建置資訊蒐集與策展平台，協助行內單位追蹤關注議題，透過 AI 篩選文章並產生洞見彙報，降低資訊蒐集、判讀與報告整理的負擔。

## 壹、專案整體規劃

### 一、功能說明

#### （一）使用流程

設定資料來源 → 自動擷取與整理 → 資訊助手評估與收錄 → 訂閱閱讀與個人收藏 → 彙報生成與站內通知。

使用者亦可透過 Agent 查詢資料或提出操作需求。功能應依工作空間及角色授權，效益以資訊整理時間、精選品質與彙報可用性評估；量化目標及服務規模於需求與設計階段確認。

#### （二）角色與權限

| 角色 | 主要權限 |
| --- | --- |
| 平台管理者 | 管理帳戶、工作空間、連接器、模型授權、預算、公告與管理紀錄。 |
| 工作空間管理者 | 管理所屬工作空間的成員、權限及內容資源。 |
| 工作空間編輯者 | 依授權維護來源、助手與彙報，調整收錄結果及編輯內容。 |
| 工作空間閱讀者 | 閱讀授權內容、訂閱助手，管理個人書籤與收藏集。 |

登入應整合公司指定的 Microsoft 身分服務。使用者可加入多個工作空間，各空間的資料與操作權限應分別檢查；連接器及模型服務由平台集中授權。

#### （三）AI 與處理原則

- 摘要與彙報應使用繁體中文，保留來源連結、涵蓋期間及生成資訊，供使用者查證。
- 助手依使用者指令評估文章，採 `0～1` 的相關性分數及可設定的收錄門檻；預設值於需求確認時核定。
- 日常擷取、評估與收錄應自動執行。人工排除或恢復須記錄原因、操作者及時間，並保留 AI 原始評估。
- 應區分處理中、完成、未收錄、略過與失敗，提供適當的重試方式；無符合條件文章時應說明原因。
- 模型用量與費用應歸屬至工作空間及功能，支援預算提示或限制。資料、指令、對話及憑證應依授權範圍管理。

### 三、專案產出：Web 應用平台

應提供可透過瀏覽器操作的平台，清楚顯示目前工作空間、資源歸屬與處理狀態。

1. **資料來源與助手**：支援 RSS、關鍵字搜尋及 Infominer 等授權服務；可設定來源、擷取條件、助手指令與收錄門檻，並提供指令草稿、來源推薦及定義版本查閱與還原。
2. **閱讀與整理**：支援文章搜尋、助手訂閱、來源追蹤、個人精選、書籤、收藏集與匯出；刪除收藏集僅移除分類關聯。
3. **彙報與通知**：可由一個以上的授權助手生成彙報，支援手動及每日、每週、每月排程，並提供刊期閱讀、內容編輯、站內通知與已讀管理。
4. **Agent 協助**：提供對話、進度、待確認操作與執行結果。寫入或敏感操作須先確認；斷線後可恢復狀態，取消及重複提交應有明確處理規則。
5. **管理功能**：提供帳戶、成員、邀請、跨工作空間來源、連接器、模型、用量、預算、公告、資料保留及管理紀錄的授權操作介面。

### 四、專案產出：API 與整合介面

#### （一）共通規格

- 採 HTTPS、JSON、UTF-8 與含時區的日期時間；受保護介面使用 Bearer Token，授權整合可使用 API Key。
- 所有查詢、寫入及匯出均須檢查工作空間、角色與資源權限；個人資料及對話限本人操作。
- 一般列表採 `offset`、`limit` 分頁；背景工作以 `202` 表示受理，另提供狀態查詢。Agent 進度以 SSE 傳送。
- 錯誤回應包含 `statusCode`、`code`、`message` 與 `requestId`；寫入、生成及發布須避免重複執行。
- 交付時應提供完整 OpenAPI 規格、請求回應範例、SSE 說明及整合驗證結果。

#### （二）核心介面

以下路徑均加上 `/api` 前綴；`W` 代表 `/workspaces/{wsId}`。同一路徑的多個方法依列示順序對應操作。

| 方法 | 路徑 | 用途與主要輸入輸出 |
| --- | --- | --- |
| GET | `/authentication/microsoft/login` | 啟動公司身分登入，導向身分服務。 |
| GET、PATCH | `/me` | 查詢個人資料、更新允許修改的個人偏好。 |
| GET、POST | `W/feeds` | 查詢來源、以 `FeedInput` 建立來源。 |
| POST | `W/feeds/{feedId}/run` | 手動擷取，回傳來源識別及受理狀態。 |
| GET | `/articles` | 依關鍵字、來源與日期搜尋，回傳文章分頁。 |
| GET、POST | `W/assistants` | 查詢助手、以 `AssistantInput` 建立助手。 |
| GET | `W/assistants/{assistantId}/articles` | 依狀態查詢助手文章、評分與收錄理由。 |
| PATCH | `W/assistants/{assistantId}/articles/{relationId}/review` | 以 `collected`、`reason` 排除或恢復文章，保留原評估。 |
| POST、DELETE | `/me/assistants/{assistantId}/subscribe` | 訂閱、取消訂閱助手。 |
| GET、POST | `/me/bookmarks` | 查詢書籤、以文章識別加入書籤。 |
| GET、POST | `/me/collections` | 查詢、建立個人收藏集。 |
| GET | `/me/collections/{collectionId}/export` | 依授權與篩選條件匯出 CSV。 |
| GET、POST | `W/briefs` | 查詢彙報、以 `BriefInput` 建立彙報。 |
| POST | `W/briefs/{briefId}/run` | 啟動生成，回傳 `executionId` 與受理狀態。 |
| GET | `W/briefs/{briefId}/executions/{executionId}` | 查詢處理狀態、原因及生成刊期識別。 |
| GET | `/me/notifications` | 查詢本人通知及已讀狀態。 |
| POST | `/agent/sessions` | 以 `SessionInput` 建立對話。 |
| POST | `/agent/sessions/{sessionId}/runs` | 以 `RunInput` 提交需求，回傳執行識別。 |
| GET | `/agent/runs/{runId}/events` | 接收 SSE 進度、訊息與待確認操作。 |
| POST | `/agent/runs/{runId}/permissions/{permissionId}/respond` | 回覆核准或拒絕；實際操作結果另行回報。 |
| PUT | `/admin/workspaces/{wsId}/llm/settings` | 設定已授權模型、任務模型與工作空間預算。 |

完整的 174 項介面及權限、輸入輸出與處理規則，列於 [API 規格附件](</Users/ckwang/Projects/work/temp/infogather_prd/InfoGather PRD_API規格附件_20261106.md>)。

#### （三）主要資料契約

| 契約 | 核心欄位與限制 |
| --- | --- |
| `FeedInput` | 必填 `title`、`connectorKey`、`sourceConfig`；連接器須已獲授權，來源設定依類型驗證。 |
| `AssistantInput` | 必填 `name`、`description`、`instructions`、`feedIds`；至少一個可用來源，`scoreThreshold` 範圍為 `0～1`。 |
| `BriefInput` | 必填 `name`、`instructions`、`assistantIds`；至少一個授權助手，可設定回溯天數與排程。 |
| `SessionInput`／`RunInput` | 對話須有 `requestId`、`scope`、`billingWorkspaceId`；工作空間情境另需 `workspaceId`。執行須有 `requestId`、`prompt`。 |
| `LlmSettingsInput` | 完整設定須有 `connectionId`、`defaultModel`；可另設任務模型與預算，且須符合工作空間授權。 |

### 五、專案產出：策展文章與洞見彙報

| 成果 | 應包含的內容 |
| --- | --- |
| 策展文章 | 標題、來源連結、發布與收錄時間、繁體中文摘要、必要本文及標籤。 |
| 助手評估 | 相關性分數、判斷理由、有效收錄狀態，以及人工調整紀錄。 |
| 彙報刊期 | 主題、涵蓋期間、來源助手、生成時間、AI 原稿及分開保存的人工編輯內容。 |
| 匯出資料 | 助手文章與個人收藏集採 CSV；管理欄位依權限提供，篩選條件與查詢一致。 |

文章收錄調整應影響後續閱讀與彙報選材；既有刊期保留生成時內容，修訂由有權者明確操作。

### 六、專案產出：部署與維運套件

1. **部署交付**：提供可部署服務、主機與網路需求、環境設定、外部服務與憑證清單，以及安裝、啟停、更新與回復程序。
2. **日常維運**：提供服務健康、背景工作、失敗重試、模型用量、預算及容量的監控與排查方式，重要異動須可追溯。
3. **備份與恢復**：定義業務資料、設定與對話狀態的備份及保留範圍，完成隔離還原演練；保留期限、恢復目標與維運分工於上線前確認。
